# Асинхронно програмиране (async/.await) в Rust

## Паралелизъм vs Конкурентност
- **Паралелизъм** — няколко задачи се изпълняват едновременно на различни нишки.  
- **Concurrency** — няколко задачи прогресират „едновременно“ чрез редуване, дори върху една нишка (кооперативно).  
- Те са ортогонални:  
  * concurrency без паралелизъм (една нишка)  
  * concurrency с паралелизъм (множество нишки) :contentReference[oaicite:1]{index=1}

## Защо ни трябва асинхронно програмиране
- Традиционният синхронен код, който блокира по време на I/O, не скалира добре при много едновременно чакащи операции.  
- Асинхронният подход позволява на програмата да *продължава да прави други неща*, докато чака I/O операции да завършат, без да разчита на множество OS-нишки. :contentReference[oaicite:2]{index=2}

## Async/.await в Rust
### Основна идея
- Ключовата дума `async` маркира функция или блок като асинхронен.  
- `async fn foo() -> T` не изпълнява веднага кода — вместо това **връща бъдеща стойност** („future“) от тип, който имплементира `Future<Output = T>`.  
- За да извлечем крайния резултат, трябва да използваме `.await`. :contentReference[oaicite:3]{index=3}

### Какво всъщност прави `async`
- `async fn` **не** изпълнява кода—той *конструира future*.  
- Тази future представлява *структура със състояние* (state machine), която може да бъде „полирана“ (полинг) докато завърши. :contentReference[oaicite:4]{index=4}

### Примерен синтаксис
```rust
async fn get_number() -> u32 {
    42
}

async fn example() {
    let value = get_number().await;
    println!("Стойността е {}", value);
}
```

Тук get_number() връща future, а .await я изпълнява до край.

### Async блокове

Можем да използваме async и без функция, като анонимни блокове:
```rust
let future = async {
    println!("Асинхронен блок");
    10
};
```
Такива блокове също връщат тип, който имплементира Future.

### .await
- .await е постфиксен оператор.
- Може да бъде използван само в контекст, маркиран с async (функция или блок).
- .await „спира“ изпълнението в текущия async контекст до като future не е готова. 

### Future и изпълнение
- Future е мързелив обект: сам по себе си нищо не прави, докато не бъде изпълнен чрез .await или чрез executor.
- За да работи асинхронният код във външна (реален) контекст, обикновено използваме async runtime като Tokio, async-std, smol и др., които изпълняват и управляват futures. 
### Async I/O
- Rust предоставя низ от асинхронни I/O функции (често чрез библиотеки/крейтове), които позволяват четене/писане без блокиране на нишката.
- Повечето от тези функции връщат futures, които трябва да бъдат .await-нати. 

### Комбиниране на няколко futures
- Често искаме да изпълним повече от една асинхронна задача едновременно.
- Това става чрез utilities като join! (напр. от Tokio), които чакат всички futures да приключат.
### Един пример с Tokio
```rust
use tokio::time::{sleep, Duration};

async fn work(id: u8) {
    println!("Start {}", id);
    sleep(Duration::from_secs(1)).await;
    println!("Done {}", id);
}

#[tokio::main]
async fn main() {
    let a = work(1);
    let b = work(2);
    tokio::join!(a, b);
}
```
Този код стартира и двете задачи асинхронно и чакa и двете да завършат.
